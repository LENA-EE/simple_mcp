# MCP DROSPR JARVIS — Инструкция по подключению

## Что это

MCP DROSPR JARVIS — сервер автоматического анализа Perl-кода.
Работает внутри банковского периметра. Данные никуда не уходят.

Подключаешь один раз к IDE — и при работе с Perl-файлами
получаешь разбор ошибок с объяснениями на русском языке.

---

## Для кого

**Разработчик** — подключает к своей IDE (Kilo, Cline, Cursor).
Помогает при ревью, рефакторинге и работе с незнакомым легаси-кодом.

**Тимлид** — один сервер на всю команду. Не нужно устанавливать
Perl::Critic на каждой машине.

---

## Что даёт

- Находит проблемы в Perl-коде: небезопасные конструкции, нарушения стиля, потенциальные баги
- Объясняет каждую проблему на русском с рекомендацией как исправить
- Показывает номер строки и конкретный код где проблема
- Группирует по критичности: от стилистики до критических ошибок

**Пример вывода:**
```
Строка 12: Two-argument open
  РЕКОМЕНДАЦИЯ: Используйте трёхаргументный open: open my $fh, '<', $filename
  Policy: InputOutput::ProhibitTwoArgOpen

Строка 34: Use of uninitialized value
  РЕКОМЕНДАЦИЯ: Добавьте 'use strict; use warnings;' в начале файла
  Policy: TestingAndDebugging::RequireUseStrict
```

---

## Что нужно для подключения

Только URL сервера — спроси у администратора:
```
http://<IP-сервера>:8000
```

Никаких ключей, паролей и токенов разработчику не нужно.
Всё уже настроено на сервере.

---

## Настройка IDE

### Kilo

Файл: `~/.config/kilo/kilo.jsonc`

```json
{
  "mcp": {
    "jarvis": {
      "type": "remote",
      "url": "http://<IP-сервера>:8000/sse",
      "enabled": true
    }
  }
}
```

Перезапусти Kilo. В списке инструментов появится `perlcritic_analyze`.

### Cline (VS Code)

Settings → Cline → MCP Servers → Add:

```json
{
  "mcpServers": {
    "jarvis": {
      "url": "http://<IP-сервера>:8000/sse"
    }
  }
}
```

### Cursor

Settings → MCP → Add Server:

```json
{
  "name": "jarvis",
  "url": "http://<IP-сервера>:8000/sse",
  "transport": "sse"
}
```

## Как использовать

После подключения просто попроси агента проверить код:

```
Проверь этот файл на ошибки: [вставь код или укажи файл]
```

```
Проанализируй ProcessPayment.pl — покажи только критичные проблемы
```

```
Найди все нарушения стиля в модуле billing.pl
```

Агент сам вызовет `perlcritic_analyze` и вернёт структурированный отчёт.

---

## Уровни строгости

| Severity | Что показывает |
|----------|----------------|
| 1 | Всё — включая стиль и форматирование |
| 2 | Строгие требования |
| 3 | Средние проблемы |
| 4 | Только серьёзные |
| 5 | Только критические ошибки |

По умолчанию используется severity=1 (показывает всё).
Если хочешь только критичное — скажи агенту: "проверь с severity 4".

---

## Проверка что всё работает

Попроси агента:
```
Вызови инструмент perlcritic_analyze с таким кодом:
open(FILE, 'test.txt');
```

Должен вернуть предупреждение о Two-argument open.

---

## Что делать если не работает

| Проблема | Что проверить |
|----------|---------------|
| IDE не видит инструменты | Проверь URL в конфиге, перезапусти IDE |
| Нет ответа | Попроси администратора проверить `curl http://<IP>:8000/` |
| Ошибка подключения | Убедись что подключён к VPN банка |

## Pre-push хук — автоматическая проверка перед git push

Хук запускается локально при каждом `git push` и отправляет изменённые Perl-файлы
на MCP-сервер. Если есть критичные нарушения — пуш блокируется.

**Что нужно на твоей машине:**
- `bash`, `curl`, `python3` — есть по умолчанию на любом Linux/Mac
- Perl::Critic **устанавливать не нужно** — он работает в Docker на сервере

### Подключение (одна команда)

**Каждый разработчик делает это один раз** — при клонировании репозитория.
Git не активирует хуки автоматически, поэтому ручной шаг обязателен.

В корне репозитория проекта выполни:

```bash
./setup.sh
```

Или вручную:

```bash
git config core.hooksPath .githooks
```

Всё. Хук активирован для этого репозитория.

### Настройка адреса сервера

Открой файл `.githooks/pre-push` и поменяй `MCP_URL`:

```bash
MCP_URL="http://<IP-сервера>:8000"   # адрес виртуалки банка
```

IP-адрес спроси у администратора.

### Как работает при git push

```
git push
  → хук читает изменённые .pl/.pm файлы локально
  → отправляет содержимое на MCP-сервер (не пути, а текст файлов)
  → severity 4-5  →  ❌ пуш заблокирован, показаны нарушения
  → severity 3    →  ⚠ предупреждение, пуш идёт
  → чисто         →  ✅ пуш проходит молча
```

### Пример вывода при блокировке

```
🔍 Проверяем Perl код через MCP JARVIS...

❌ billing.pm — 2 блокирующих нарушения:
  Строка 14 [severity 5]: Two-argument open
  Строка 27 [severity 4]: Backtick operator

Пуш заблокирован. Исправь нарушения severity 4-5 и попробуй снова.
```

### Если MCP-сервер недоступен

Хук не блокирует команду. Выведет предупреждение и пропустит проверку:

```
⚠ MCP недоступен — проверка пропущена
```

Это намеренно: недоступность сервера не должна останавливать разработчиков.
